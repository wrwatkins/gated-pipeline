# Gate 7 — Security review

Role: security-reviewer. Read docs/PROCESS.md, pipeline.config.json, STACK.md and the applicable upstream artifacts.

Review .gated-pipeline/checklists/security-review.md and the actual sensitive surfaces. Run configured SAST and dependency checks; document unavailable checks and triage. Review input provenance and current authority at each entry and recovery path, including cross-user behavior and logging/telemetry. No unresolved BLOCKING, CRITICAL or HIGH finding can pass. Never downgrade a failure just because it lacks a finding object.

Then run the adversarial pass and record it as the `adversarial` check (required on `full` and `chore`), scaled to the diff, in this order: (1) threat model: what the attacker wants, controls and does not control; (2) boundaries: list the changed paths and name every trust boundary they touch (authentication and role gates, tokens, CSRF and webhook signatures, parsers of external input, uploads and storage, secrets, personal-data egress, money, subprocess and path handling, CI permissions and triggers, dependency pins, model prompt input, switches that can silence alerts or logs, and the pipeline's own validators and instructions); (3) attempts: at least one probe per boundary, each recorded as the exact probe, the expected refusal and the observed result, run against the reviewed head in a scratch checkout or the test suite, never as destructive or credentialed traffic against production; (4) findings for every attempt whose result differed from the expected refusal; (5) what could not be checked, with the reason, so a gap is never presented as coverage. When the diff touches no trust boundary, say so and give the reasoning per changed path; an omitted or empty pass fails the gate. At a merge turn, scope the pass to the merge delta and cite the earlier pass. Record `context: "fresh"`. The pass records what was attempted and what held; it does not prove the absence of vulnerabilities.

This gate must produce PASS or FAIL. Individual checks may be n/a only with an applicable, recorded reason.

Write an attributed attempt using .gated-pipeline/schemas/evidence.schema.json. Report observed results. On rework, record a new attempt and revalidate downstream gates; never replace a historical failure. Next role: ops-reviewer.
